# 読込・索引構築の進捗と取消

2026-11-04。🟢 [Done] .u3d読込・復旧・USD取り込みで、Rust所有の操作ID・工程別進捗・協調取消を共通化した。文書・共有形状・GPUの状態はRust側で保持する。

## 操作

処理中は画面下端に工程、工程内のカウンター、進捗バー、取消ボタンを表示する。狭幅でも下端へ留める。復旧／USDのモーダル内にも同じ操作を表示し、モーダルが開いている時はその中の取消またはEscapeを使う。通常の文書読込は下端の取消ボタンを使う。

工程は読込・解析・形状読込・変換・三角形化・検証・頂点・エッジ／面・配置・確定。読込とJSON解析はバイト、SDK形状読込は頂点、三角形化は面のカウンターを使う。総数の分からないSDK内部解析／変換、検証と確定は不定進捗で表示する。形状工程のカウンターは完了した一意のメッシュ数、配置工程は走査した文書オブジェクト数で、非表示オブジェクトもその走査数に含む。ミラー配置が2件でも元オブジェクトは1件として進む。数値へホバーすると単位を確認できる。全工程の時間や残り時間の割合を表すものではない。

英語・日本語・简体中文に対応し、ラベル・progressのアクセシブル名・取消ボタンを付ける。形状やフレームの大きな配列を進捗IPCへ追加しない。

## 取消の確定境界

`get_load_progress`は操作ID（文字列）、種別、工程、完了数／総数、取消中／取消可能の状態だけを返す。`cancel_load(id)`は現在の取消可能なIDにだけ作用する。画面が表示したIDを要求時に固定して送るため、旧要求を次の読込へ流用しない。

RustのTasksは操作単位のAtomicBoolを所有する。頂点／エッジ／面の既存チェックへ接続し、配置の走査は128オブジェクトごと、配置BVHは1,024ノードごとと構築前後に取消を確認する。索引構築はEditorロック外で実行する。

確定直前は取消APIと同じロックを取り、取消済みなら中止、未取消なら「確定中・取消不可」へ進む。両者の競合では一方だけが成立する。復旧はチェックポイントの書込前がこの境界で、その後の文書置換・復旧元消費の順序を維持する。USDも一括追加直前に境界を設ける。

取消・エラー・終了ではGuardが操作状態を解除する。確定前に所有Guardが失われた場合は、ワーカーの取消フラグも立てる。遅れて来る工程更新は別IDと確定済み状態を変更しない。前回の取消フラグは次の操作と共有しない。

## 表示と負荷

LoadProgressはWebView内のuseSyncExternalStoreで進捗を共有し、下端とモーダルの両方があってもポーリングを一本にする。250ms間隔で、小さな状態に変化がある時だけ再描画する。通信を重複させず、購読がなくなればタイマーを止め、遅延した結果を破棄する。

取消を受け付けると取消中を表示する。確定中は取消ボタンを無効化する。操作が終われば進捗表示を消す。期待された文書読込取消はエラー表示にせず、復旧／USDでは対応する翻訳済みの取消結果を表示する。

## 制限

ファイル選択・未保存確認のネイティブダイアログは操作開始前で、それぞれのダイアログで取り消す。ファイルI/O・JSON解析は後述のチェックポイントで協調取消する。文書検証も形状ごと・物体128件ごとに取消を確認する。これらは処理境界で取消を確認するため、要求から停止まで待つ場合がある。ソート／単一BVH分割なども協調取消であり、即時停止の保証ではない。

確定に入った後のチェックポイント書込やイベント配信は巻き戻さない。USDの取得キャッシュは取消時も残る場合がある。進捗の表示はWebViewごとのポーリングで最大約250msの遅れがあり、短い工程は表示されないこともある。現時点ではメイン画面・復旧／USDダイアログへ表示し、分離パネルには専用UIを追加していない。

## I/O・JSON解析・USDの詳細進捗（2026-11-04）

`load_io`でユーザー操作の.u3d読込・復旧とUSD中間JSONの読込を共通化する。Fileは64 KiBずつ読み、読込前後とチャンクごとに取消を確認する。metadataのサイズだけを信頼せず、増大したファイルも上限＋1 byteまでで拒否する。従来どおり文書128,000,000 bytes、USD中間出力64 MiBが上限。読込中の一時データはRustだけが所有する。

JSONはチェック付きReaderを使うserde_jsonのストリーム解析へ移した。64 KiB消費するごとにParse工程を更新し、取消を確認する。長い文字列など単一トークンの途中にも到達するチェックで、単に解析前後だけを確認する方式ではない。末尾の不正データも拒否し、取消エラーは`LOAD_CANCELLED`へ統一する。解析が成功しても、従来の検証・索引準備・取引Stamp・確定境界を通るまで文書を公開しない。

USDアダプターはダウンロードの64 KiB単位のバイト数、SDK Stage.Open中の不定進捗、prim走査と頂点抽出の進捗を、作業ディレクトリの小さな原子的status JSONへ書く。更新は通常100msに一回へ抑え、工程変更と完了では即時更新する。Rustは既存の50ms子プロセス監視で受け取り、現在の操作IDへ関連付ける。パス・アセット名・頂点を進捗IPCへ含めない。取消なら子プロセスをkill／waitし、作業ディレクトリを後始末する。SDK内の解析量はAPIから取得できないため、架空の割合を表示しない。

Rust変換は128面ごとに三角形化の進捗を更新する。凹ポリゴンのear clipping内部にも取消確認を入れる。I/O・解析・SDK・三角形化で失敗／取消しても既存文書・Undo／Redo・復旧元を変更せず、最後の確定境界は従来どおりとなる。起動時の復旧候補スキャンは[独立したワーカー](recovery.md)で行う。Save／チェックポイント書込はこの読込操作の対象外。

UIはバイト数をKiB／MiBへ縮め、hoverとaria-valuetextは正確なバイト数を示す。面・頂点・形状・物体の単位を英語／日本語／简体中文で区別する。総数0では不定進捗に切り替える。段階ごとにカウンターを切り替える方式で、全工程の経過時間の割合ではない。

### 費用と確認範囲

合成JSON 1,700,001 bytesのdebug単独実行では、従来のfrom_sliceが45,911µs、チェック付きReaderが113,517µsだった。同じ値へ復元することを検証した。約2.5倍の差はこの合成入力1回分であり、releaseや全シーンの比率・取消時間を保証しない。この初回値に対する後続の高速化は次節に記録する。チェックなしのスライス解析との追加費用は残る。


OSの単一read／open呼出しはRustのフラグで途中中断できず、SDK監視もスケジューラの影響を受ける。64 KiB／50msは確認間隔であり、取消完了時間の上限ではない。文書／Meshのvalidateは次節の粒度で確認し、最大1ポリゴン内などの処理でも確認点までの待ち時間は残る。
