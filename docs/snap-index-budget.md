# CPUスナップ索引の構築予算

2026-11-02。🟢 [Done] .u3d読込・復旧・USD取り込みで、新しく準備するCPU索引の容量を構築前に見積もり、予算超過時は採用前に拒否する。入力メッシュの既存上限とは別の制御である。

## 設定と判定

既定512 MiB。`U3D_SNAP_INDEX_BUDGET_MIB`で1〜4096の整数を指定できる。Tauriアプリを起動するプロセスの環境へ設定する。無効な値は無視せず`SNAP_INDEX_INVALID_BUDGET`として失敗する。起動中に設定を変更するUIは今回追加していない。

```sh
# 開発起動の例
U3D_SNAP_INDEX_BUDGET_MIB=128 npm run tauri dev
# 合成シーンで設定値の反映を確認
U3D_SNAP_INDEX_BUDGET_MIB=16 python3 scripts/benchmark-snap-memory.py --prewarm-scene --cases shared --runs 1 --output /tmp/snap-budget.json
```

索引の構築用予約値は、次の保守的な重みで計算する。MiB=1,048,576bytes。

| 対象 | 予約値 |
|---|---:|
| 不変形状の三角形 | 1,024 bytes／三角形 |
| 表示配置（ミラーは追加1配置） | 1,024 bytes／配置 |
| 一意の形状 | 4,096 bytes／形状 |

形状の重みには、重複しない頂点・エッジ、Vecの余剰容量、頂点／エッジ／面BVH、トポロジーHashMapと一時領域の費用を見込む。配置の重みには、行列・境界・配置木・葉／配置Map・構築用の葉配列を見込む。プラットフォーム固有のアロケータをモデル化した厳密な上限ではなく、構築を許可するか決める概算値である。

同一Mesh Arcは別IDのエイリアスでも一回だけ数える。座標が等しくても別Arcなら別形状とする。非表示の参照メッシュは事前構築対象なので数え、未参照アセットは除外する。文書読込・復旧では表示中のプリミティブと表示配置も数える。隠れたプリミティブは今回事前構築しない。

計算はchecked演算で行い、桁あふれも拒否する。見積りが予算と同じなら許可し、1byteでも超えれば拒否する。USD用の形状束は全アセット参照を収集して判定してから、最初の形状を構築する。文書用は文書検証後、最初の索引構築前に全体を判定する。

構築中は各メッシュ完成後に索引所有Vec／Boxの保持容量の累計も予算と比較し、文書用は配置木完成後にも確認する。これは完成後の検査で、個々の割当を途中で制限するものではない。超過時は束を破棄して`SNAP_INDEX_BUDGET_EXCEEDED`を返す。予算超過の表示には英語・日本語・简体中文と容量を含める。

## 状態と診断

拒否時は文書・Undo／Redo・dirty・既存キャッシュを変更しない。復旧元を消費せず、チェックポイント書込にも進まない。USD変換やファイル解析の結果は索引の採用前に破棄する。ただしUSDのダウンロードキャッシュまで巻き戻すものではない。キャンセルは既存のチェックを継続する。

`get_snap_diagnostics`の`last_preparation.budget`に、成功した準備の`limit_bytes`、`estimated_working_bytes`、`triangles`、`instances`、`shapes`を記録する。`memory`／`buffer_bytes`は実際の保持バッファ容量で、予算の予約値と区別する。拒否結果で前回成功の記録は上書きしない。別epochの古い診断を表示しない規則も維持する。形状配列やパスをIPCへ追加していない。

## 範囲と限界

この予算は**新たに準備する索引束**を対象とする。アプリ全体のRAM／RSS上限やVRAM上限ではない。入力文書・Meshのデシリアライズ、USD SDK／変換・ダウンロード、既存文書・既存キャッシュ・Undo履歴・外部に残るジェスチャーArc・GPU資源は含まない。USD追記の判定も追記する形状束が対象であり、既存キャッシュと合算していない。

通常編集での配置木の拡張、直接コアAPIから追加した形状の遅延構築も今回の予算判定の対象外。予算を大きくしても空きRAMがある保証はなく、OOMを確実に防止する機構ではない。予算を小さくすると、実際にはその容量に収まる形状でも保守的な見積りで拒否する場合がある。2026-11-04に[未参照キャッシュの追い出し](snap-cache-retention.md)を追加した。使用中の索引・配置木の圧縮や新規準備と既存キャッシュの合算判定は次工程。後続工程で[工程別進捗と取消](load-progress.md)を追加した。

## 検証

通常Rust106件が成功。新規3件で、設定値の境界・不正値・算術あふれ、容量検査の境界、重複Arc・エイリアス・未参照／非表示形状・ミラーの数え方、見積りの完全一致と1byte超過、構築前の拒否、キャンセル、現在文書・Redo・dirty・キャッシュ保持を検証した。

別プロセスで16 MiBを指定し、6,561頂点／144配置の合成文書を準備した。診断の設定値は16,777,216bytes、保持バッファ容量は581,176bytes。1回の機能確認であり、性能比較のための統計ではない。[実行記録](benchmarks/snap-budget-20261102.json)。実RSSはこの予算を超えても、上記の対象外のメモリを含むため矛盾しない。
